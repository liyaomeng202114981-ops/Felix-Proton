# 原图标重开与启动耗时

## 正常退出后打不开

主窗口关闭之后，专用 Wine 运行时和采集、馈送服务可能继续驻留。旧控制器只检查服务是否为 `active`，容易把退出后的残留当作可用客户端。窗口消失也可能早于 Chromium 进程退出，立即重开会碰到这一段收尾。

原图标继续使用官方 Launcher。控制器用同用户、同前缀、同服务调用代和 cgroup 核验窗口与进程。重复点击时，只有已存在的稳定主窗口才走保持会话路径。旧窗消失后，等待已知辅助进程收尾并核验运行时身份，才能恢复或暖重开。未知进程、启动中窗口和不匹配的服务绑定需要等待或退出恢复流程。

暖重开保留已验证的专用 Wine 服务器、桌面采集和馈送，使用新的应用服务启动 Launcher。判定重开成功需要新主窗出现，并确认摄像头接收端在此后继续收到新帧。旧会话不满足复用条件时走完整启动。专属直连切换也在确认旧客户端退出后生效。

## 实测及排查

| 样本 | 原图标启动结果 |
| --- | --- |
| 原回收再完整启动 | 两次确认退出后重开，恢复预览约 22.4 秒和 21.5 秒 |
| 暖重开 | 两次新主窗约 12.6 秒和 13.2 秒出现，约 13.0 秒和 13.6 秒确认预览 |
| 切换至伴侣专属直连 | 已确认旧窗退出后经原图标暖重开，控制器约 9.5 秒确认预览，原 Wine 和采集服务代保持 |

上表包含不同启动条件。复查应分别计时新主窗出现和实际帧恢复，并验证退出后立即点图标、已有窗口时重复点图标两个场景。

Electron 就绪后还有应用配置、更新判断及并行初始化。慢样本中，一次在线配置约 5.12 秒，另一次初始化并行组由硬件评分最后完成，其结束比用户画像超时晚约 1.52 秒。关闭 GPU 渲染只做了一轮有效对照，消除了启动前的 GPU 退出提示，12.96 秒仍在默认样本的耗时范围内，最终保留原 GPU 配置。

回退时先让伴侣正常退出，再恢复同一批次备份的控制器与 Launcher 启动脚本。原桌面项、账号前缀和采集安装账本继续使用。

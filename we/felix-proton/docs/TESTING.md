三轮真实目录查询每轮返回 17 个合格候选，首次就绪时有 14 条 IPv4/TCP 规则。模拟 UU 接管路由后，逐条验证 CM TCP 命中原出口，同地址的其他 TCP 端口、UDP 和无关地址命中模拟 UU 路由。移除模拟 UU 后复查选路。守护退出后恢复隔离环境的规则与路由，写前账本已清理。三轮都由替身接收到一次就绪通知调用，宿主 IPv4 规则和路由前后一致。

实际会话日志另记录规则从 5 条增至 19 条，退出时完成清理并停止守护。退出同时记录的 `FileNotFoundError` 见下节。上述计时的范围是 CM 保护就绪，完整桌面启动耗时和游戏内延迟未测。

## CM 退出状态复测

本机日志显示，wrapper 清理 keeper 标记并记录共享会话为空后，旧守护回收了规则，却将随后读取 keeper 身份时遇到的 `FileNotFoundError` 记为 `guard_error`。

前后版本使用临时 keeper、合成端点和一次性网络命名空间对照。分别让 keeper 标记先删除和 keeper 进程先退出。旧版两种情况下均回收规则，但留下 `error`。新版两种情况下均记录 `stopped`，事件依次为 `rules_ready`、`rules_removed`、`guard_stopped`。隔离规则和路由恢复，账本删除，宿主 IPv4 规则和路由前后一致。

70 项集成测试通过，包括启动时缺少 keeper 和其他文件读取失败仍报告错误的对照。回收失败仍由原有错误路径报告。本次同步源码、测试和说明，发行版构建继续暂缓。

## 从公开仓库运行代码测试

以下命令各自从仓库根目录开始，以普通用户运行，不使用 `sudo`，不修改 `HOME`：

```sh
cd we/felix-proton/src/native-ux
python3 -B -m unittest discover -v
```

这些测试使用临时目录和替身启动器，不启动真实 Steam、UU 或游戏。`test_policy.py` 另外通过 `unshare` 创建短期隔离网络，在其中建立合成接口及规则；不会把测试规则写入宿主机或当前 UU 会话。需要 Python、`ip`、`unshare` 及系统允许的普通用户命名空间。环境不支持时，相关用例会跳过；报告应保留通过、失败和跳过的实际数量，不能把带跳过的结果写成完整覆盖。不要为通过测试擅自调整 AppArmor、sysctl 或系统权限。

按改动范围可先运行较小的回归组：

```sh
cd we/felix-proton/src/native-ux
python3 -B -m unittest -v test_flow test_steam_window
python3 -B -m unittest -v test_endpoints test_cm_live test_cm_guard test_policy
```

前一组检查启动顺序、重复打开已有 Steam、URI/参数和异网 Steam 拒绝；后一组检查 CM 发现、活跃 socket 归属、策略及退出清理。修改相关公共逻辑后，再运行完整套件。

被动采集器的解析及游戏路由判断测试单独运行，使用 `src/test-runtime-felix/net_beta.py`。

```sh
cd we/felix-proton/src/live-watch
python3 -B -m unittest discover -v
```

不要直接运行或导入 `watch.py` 来做“语法检查”：它在顶层启动采集。需要纯语法检查时使用 AST 解析，或只运行已有测试。

2026-11-05 源码发布前重新运行两套测试：集成 64 项、采集器 16 项，均无失败、无错误、无跳过。详见 [本次工作说明](WORK_REPORT.md)。

## 后续改动应保留的行为

- Steam 先开时可建立专用网络；UU 先开不会自动启动 Steam。
- 原生 Steam 保留各游戏原有的 Proton 选择、兼容数据目录及启动参数。启动层不额外注入 UU 专用的 Fsync/WoW64 环境选项。
- `steam://` 和命令参数原样转发；重复点击普通 Steam 图标能够处理已有同网实例。
- 已存在其他网络中的 Steam 时明确拒绝混用；不能通过杀进程或偷偷重开 Steam 来使测试通过。
- 只有经 CM 目录或严格日志规则确认的端点才有资格被保护。Steam 拥有的任意 socket 并不自动等于 CM。
- 规则只匹配明确的 IPv4 地址、TCP 端口；不能扩大成整个 IP 段、所有 443、下载 CDN 或全 Steam 代理。读取失败、端点过期、规则冲突及写入失败须保持可解释的处理结果。
- 现有通过 UU 建立的连接不能被突然改换源地址；退出只清理由该保护程序登记的规则。

## 实机验收边界

日常排查先读取状态和已有日志，方法见 [DIAGNOSTICS.md](DIAGNOSTICS.md)。测试代码通过不授权操作正在运行的客户端。真实切换由用户在 UU 界面完成；不要自行停止加速、重启/杀掉 Steam、启动游戏或更改游戏配置。

用户复测时记录本地时间、选择的操作和可见结果，区分“点击开始”“客户端显示成功”“停止完成”“Steam 重连”等阶段。不要以 WinTUN 创建、路由增加或采集器的事件信号代替客户端成功。

同一网络命名空间表示连接有机会遵循相同路由，**不表示所有游戏流量都被加速**。仍由 UU 所选游戏、区服、路由模式及节点决定匹配范围；已有连接可能需要自行重连。没有实际游戏流量时，路由查找只能证明预期路径，不能据此声称游戏加速、延迟收益或反作弊兼容已验证。

CM 保护当前只覆盖已发现的 IPv4 CM TCP 端点。未发现的 CM、IPv6、下载 CDN、游戏自己的登录/游戏连接以及真实外网故障仍不在保证范围。相同目标 IP 与端口被其他程序使用时也会匹配规则。

## 尚未解决与明确不处理的事项

- 先前内核崩溃已根据本机用户的排查结果移出本项目待排查清单。归因见 [当前状态](CURRENT_STATE.md)。
- 用户询问的约 25% CPU 已定位到 Steam 的 shader 后台处理（`fossilize`），不是 CM 保护占用。用户明确要求不处理；不要停止编译、关闭 shader 功能或改相关设置。采样结论见 [工作说明](WORK_REPORT.md)，它是一个历史时点的结果，不是当前负载。
- 当前属于本机验证的本地预览；异机安装、所有发行版、所有游戏均未验收。历史 netfix2 的路由性能工作主要消除了 netfix1 引入的回退，不能宣传成比原始 WE-Proton 快数倍。

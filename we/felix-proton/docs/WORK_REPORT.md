## CM 保护的机制

普通图标调用 Python 启动层，启动层确认 wrapper keeper 的用户、启动时间及命名空间身份。在 UU 尚未创建加速网卡时保存 pasta 出口；依据 Valve CM 目录和严格匹配的 Steam 日志候选发现端点，在私有网络中建立专用路由表及目标 IP、TCP 端口规则。

保护范围不扩大到全部 TCP/443、全部 Steam IP、下载 CDN 或游戏流量。相同目标地址与端口被其他程序使用时也会匹配。已经通过 UU 建立的连接暂缓接管，避免中途更换源地址。程序按自己的归属记录清理规则；不修改宿主机路由。CM 功能位于 Python 启动层，本轮未重编 test.1 Wine/Proton。

## 未解决、接受或暂缓的事项

- 内核 `__run_timers` panic 和 workqueue 警告：根因未定，没有证据直接归因于 UU，也没有修复结论。
- 启动加速约 10～30 秒：用户可以接受，虚拟网卡建立前的部分等待尚未全面归因。
- UU 主窗口自由缩放：客户端固定尺寸，用户决定暂缓。
- 异机安装、更多发行版、游戏、节点及 IPv6：尚无全面端到端验收。未发现的新 CM、下载 CDN 和游戏自身连接不在当前保护保证范围内。
- 退出游戏后的历史 CPU 占用：已定位到 Steam Fossilize 后台着色器编译，用户要求保留设置；此项完成归因，不列为网络修复。

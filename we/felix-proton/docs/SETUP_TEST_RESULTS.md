## 实际全新安装

从候选安装包解压的代码快照运行，三个src目录53份文件的SHA完整记录。实际执行的Python/测试/C代码与最终发行安装代码逐字核对；验收后只补说明/测试报告与构建清单。候选包SHA为`cc3d590659ea64ab33d0c84bf5a4592b8b803c5e7883e9f83a8aef6cf12524bb`，最终附件以发行页SHA256SUMS为准。

采用独立user/net/PID/mount namespace、隐藏真实HOME的空目录、私有DBus和Xvfb，不登录账号、不运行游戏、不使用宿主鼠标键盘。Steam为原生可执行替身和标准steam.desktop夹具；UU为用户提供的真实官方6.21.1.73安装程序，SHA `3c5df7f4e2386635b0fb8e9dd7c88ffa6546cfcf39b72f0319260ad810d8b5e5`。固定运行器经Steam Linux Runtime实际运行，未将宿主直跑计为通过。

以下完整流程通过：

1. `check`通过且未创建前缀；真实固定归档解包到新Steam根目录，Windows初始化创建新registry。
2. 新`setup.py install`实际打开官方UU安装器；仅对私有窗口按当前标题/类/PID/可见性守卫点开始安装，确认默认客户端文件安装成功，未导入旧prefix。
3. 合成Steam入口原Icon/URI保持；新UU入口使用已安装客户端生成的纯品牌PNG（SHA `7213227623b0913e2faf3b449dd5bcb9e15deb2e3c6fd418e2ef36565eeecfae`），不是安装器纸箱或通用网络图标。品牌资源不随包分发。
4. `status`退出0、无冲突；重复安装保持配置、active和两入口字节不变；原生Python替身以UID1000加入同一prefix keeper网络。
5. 实际配对后台采用/移除原连接不改入口；`restore`恢复原Steam夹具，保留prefix/config。所有测试后代进程已清空，宿主IPv4规则/路由前后逐字相同。

上述完整安装使用显式wrapper/pasta路径。另在全新隔离HOME/XDG中，通过最终引导的`obtain --offline`实际校验全部三材料，安装真实wrapper/pasta到私有哈希目录，核对0755、当前UID、SHA和`--help`能力；重复安装inode/mtime/mode/hash保持。它证明自动准备材料的本机文件流程，没有冒充公开HTTPS下载验证；发行附件发布后还应独立下载核验。

另在全新前缀中实际运行自有Win32程序，文件I/O、GetAdaptersAddresses和默认wrapper/umu路径退出通过。无manifest程序的兼容版本返回值不用于声称Windows版本兼容。
